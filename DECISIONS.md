# DECISIONS.md — judgment calls made during the build

Per SPEC: ambiguities get resolved and logged here rather than blocking.

1. **Naming.** Kept **SKILLMON** as the working title. Alternatives considered per §2: Grindmon, Levelings, Questline. "Skillmon" reads best on a title screen and is IP-safe (original creatures, no franchise references anywhere in copy).
2. **Damage rounding.** Spec gives 1.5×/0.75× effectiveness on integer damage. Rule: `damage = max(1, round(base × effectiveness))`. So a normal hit with advantage = 2, with disadvantage = 1, and a critical with advantage = 3. Unit-tested in `lib/game/__tests__/battle.test.ts`.
3. **Arena battle structure.** Each arena has a wild work-demon gate, then the gym leader. First visit fights the wild demon (arena 1 = **Buggon**, matching the film path); after beating it, the next battle is the leader, who grants the badge. Progress tracked in `save.arenaWildBeaten`.
4. **Gym leaders are typed** (`leaderType` in `content/arenas.ts`) so the Logic→Influence→Craft→Logic triangle shows up in PvE damage and the +10 type-advantage XP bonus, per §7. Wild work demons are typeless (neutral damage).
5. **Persistence in Demo Mode is localStorage** (`lib/state/save.ts`), shaped to mirror the Supabase schema (`supabase/schema.sql`) so swapping in Postgres later is a storage change, not a rewrite. No Supabase project is required to run the demo. Magic-link auth is Phase 5+ work.
6. **Quiz fallback strategy.** `/api/quiz` tries Claude only when `ANTHROPIC_API_KEY` is set (one retry on invalid JSON, zod-validated, options shuffled server-side with the answer index remapped). The client also enforces its own 6s timeout and falls back to the local bank *client-side*, so a hung network can never stall a filmed battle.
7. **Custom skills offline.** Without an API key, a custom skill still forges a creature: deterministic namer + type inference from keyword hints (hash-based otherwise) in `lib/ai/creatures.ts`, sprite = the type's procedural SVG silhouette with a seed-driven hue shift. Quiz questions for unknown skills fall back to a learning-science bank ("spaced repetition", "active recall") — honest questions, just not skill-specific. With a key, Claude writes both the creature line and real skill questions.
8. **Sprite pipeline.** Nano Banana (Gemini `gemini-2.5-flash-image`) reference-chaining is implemented in `lib/ai/gemini.ts` (stage 0 from prompt, stages 1–2 passing the previous PNG as reference). It is inert without `GEMINI_API_KEY`; procedural SVG sprites are the default art everywhere, which also keeps Demo Mode fully offline. Supabase Storage upload is the wiring left for when a project exists.
9. **Missed-question return.** Up to 2 previously-missed questions (same skill) are mixed into each battle's question set — the spaced-repetition seed from §6, stored per-save.
10. **Wrong-answer pacing.** Correct answers auto-advance (~1.3s, scaled by Film Mode) to keep battles snappy; wrong answers wait for an explicit Continue so the correct answer + explanation actually get read (pillar 3) and so a filmed take never gets rushed off screen.
11. **Question count.** 8 questions per battle covers the worst case (5-HP enemy, no crits, 2 misses = 7 questions); if a battle somehow runs longer, questions loop rather than crash.
12. **Fonts.** "Monospace-arcade" direction realized with Silkscreen (display/arcade) + IBM Plex Mono (body) via `next/font` — self-hosted at build time, no runtime font requests.
13. **Defeat costs nothing permanent.** No XP loss on defeat (only a loss tally). The learning loop should punish nothing except skipping the explanation.
14. **Sound** was left out entirely (spec lists 2–3 stingers as optional); animation beats carry the demo.
15. **Habitat (post-spec addition).** Unlocked creatures live in a decorable den (`/habitat`): pet and play with them for mood, place decor props. Every prop is earned by playing — wins, badge counts, arena wilds, evolution stages, forging a custom creature — so the collection itself is the reason to battle again. Locked items show exactly how to earn them.
16. **Mood loop.** Mood (0–100) rises from petting (+6), playing (+4), decorating (+3), and winning battles (+5); it decays −10 per day away (floored at 20). At mood ≥ 70 the creature is Happy and earns **+10 XP per victory** ("Happy creature" line in the breakdown) — care feeds progression without punishing anyone below the bar.
17. **Demo Tools panel.** In Demo Mode a floating "▚ demo" console (Home + Habitat) grants +60 XP, forces level-ups, unlocks all arenas + decor, maxes mood, and resets the save — so the whole game can be exercised in seconds. Hidden automatically in Film Mode (debug UI never enters a take).
18. **Habitat minigames.** Three tiny games in the habitat's play modal, one per type: **Bit Catch** (logic — catch falling bits, dodge bugs, 30s), **Shard Stack** (craft — timing-based stacker, only the overlap survives, 8 to win), **Echo Chamber** (influence — Simon-style star sequences, 8 rounds to perfect). The creature's own type's game is starred but all three are open. Payouts go to *mood only* (`moodForScore`: min +2 for finishing, cap +15) so battles remain the XP engine; best scores persist per save. Pure math (payout curve, stack overlap) lives in `lib/game/minigames.ts` with unit tests.
19. **Timer-throttling-proof game loops.** Browsers throttle `setInterval` to ~1Hz in hidden tabs, which broke fixed-step physics during testing. All real-time loops now use wall-clock delta time (capped at 100ms/step) and swept collision (segment-vs-band, so a fast step can't tunnel through the catch zone); Shard Stack's oscillation is a wall-clock sine. Games slow gracefully under throttling instead of breaking.
20. **Visual quality pass (post-spec).** Moved from flat "cartridge pixel" toward a modern monster-collector look: every sprite mass is shaded with a radial body gradient (lit core → mid → dark rim) plus a specular gloss and a breathing aura; eyes got gradient irises, double catchlights, and periodic blinks (SMIL). Gradient/filter ids are scoped per instance with `useId` so multiple sprites coexist. The dais gained a volumetric light beam, rotating conic energy ring, and a masked floor reflection; evolution adds rotating god-rays and expanding shockwave rings; every screen sits on an `Atmosphere` layer (drifting nebula blobs in the three type hues, deterministic star field, rising motes — SSR-safe, no `Math.random`). Panels became glass (backdrop-blur, gradient border, inset highlight).
21. **High-res raster art path.** True painted "Palworld-style" art comes from the Nano Banana pipeline: `npm run sprites` (scripts/generate-sprites.mjs) generates all 9 starter stages with reference-chaining and rich style prompts, saves PNGs to `public/sprites/`, and rewrites `content/generatedSprites.ts` so the app auto-prefers them over SVG. Requires `GEMINI_API_KEY` (env or .env.local); no key was available in this environment, so the SVG upgrade carries the demo until one is added.
22. **Generated art is live.** `npm run sprites` was run: all 9 starter stages are real Nano Banana renders in `public/sprites/`, committed to the repo and served statically (no runtime API cost). Prompt lessons learned, encoded in the script: (a) never put hex codes or literal strings in an image prompt — the model rendered "#0A0D1E" as text in the corner; (b) reference-chaining alone makes stage 1 nearly identical to stage 0, so each stage now specifies an explicit pose/silhouette change ("coiled hatchling" → "reared up like a cobra" → "flared hood") plus a CRITICAL instruction demanding an unmistakable transformation; (c) asking for "3D character render, PBR, studio key + rim light" holds the Palworld look, where a generic "digital art" prompt drifts to flat 2D.
23. **Raster sprites get a radial edge mask.** The renders carry a baked-in dark studio backdrop, so `CreatureSprite` masks generated images with a radial fade — the square edge dissolves into the page and any corner artifact disappears, without needing background removal.
24. **Saves re-hydrate their creature line.** A save stores a snapshot of its `CreatureLine`, so newly generated art (or edited lore) would never reach an existing save. `loadSave()` now re-merges the current definition for built-in starters by id; custom creatures keep what they were created with.
25. **Redirects moved out of render.** Home and Habitat called `router.replace()` during render when no creature existed, which triggers React's "Cannot update a component while rendering a different one" warning and risks a loop. Both now redirect from a `useEffect`.
26. **Auto-demo drives the real app, not a reel.** Rather than a scripted video mock, an `autopilot` store (sessionStorage-backed, survives navigation) turns on per-screen auto-behaviour: starter select picks a line, the battle answers correctly on a beat, the habitat pets/decorates/plays, and each screen sets its own narration caption. It's the actual product on camera, so the demo can never drift from the build.
27. **Two cuts.** `autopilot.full` splits the tour: the default **90-second film cut** matches the spec's §10 sequence and ends resting on the evolved hero shot (measured 89s end-to-end); **full tour** continues into habitat, mini-game and dex (~2min). Entry via title-screen buttons, the demo panel, or URL — `/?auto=1` (film) and `/?auto=full` — so filming is "load URL, hit record, walk away".
28. **Battle count is derived, not hard-coded.** The tour battles until `creature.stage > 0` rather than assuming "two fights", so it still reaches the evolution beat if the XP curve is retuned (a 3-battle cap guards runaway).
29. **Loading gap became narration.** The quiz round-trip left ~7s of stale caption per battle. The autopilot now captions the `loading` phase with "Writing fresh {skill} questions for this fight…" — turning the one unavoidable wait into the part of the pitch that explains the questions are generated.
30. **Auto-demo hides its own furniture.** While autopilot runs, the demo-tools panel is hidden and the cursor is set to `none`, so a recording has no stray pointer or debug UI. Esc exits at any point.
31. **Design system v2 — "naturalist field guide" (replaces the night-arcade look).** Once the creatures became warm, studio-lit 3D renders, the dark-navy/pixel/CRT chrome fought them and read as generic AI-app. New system: warm bone paper (`#f7f2ea`) with espresso ink, white cards with soft layered shadows, fine paper grain instead of scanlines, and **Fraunces** (variable serif, SOFT/WONK axes) for display paired with **Plus Jakarta Sans** for UI — deliberately not a monospace or a system default. Type colours were deepened (`#0e9f6e` / `#7c3aed` / `#c2760a`) to hold contrast on paper, and blue was dropped entirely per the brief: XP now reads gold.
32. **Portrait medallions turn a constraint into the concept.** The generated PNGs carry a baked-in dark studio backdrop, which would smear as grey haze on a light page. Rather than attempt background removal, every creature is presented inside a dark `.plate` medallion — so the backdrop reads as deliberate framing, like a plate in a field guide. `--plate` is tuned to the renders' own backdrop so the masked art dissolves into it with no visible square, and the sprite mask crops tighter than v1. The habitat reuses the same surface as a lit vivarium, as do the mini-game fields (with `.plate-ink`/`.plate-dim` text helpers for contrast).
33. **Class rename over churn-avoidance.** `font-arcade` was renamed to `font-display` across 11 files via a Node script (not PowerShell — which mangled UTF-8 em-dashes earlier in this build) rather than leaving a misleading class name pointing at a serif.
34. **Removing the CRT overlay fixed screenshots.** The fixed-position scanline layer had been silently breaking the Browser pane's screenshot capture all build; with it gone, every screen could finally be reviewed visually — which immediately surfaced three problems worth fixing: title creatures reading as grey smudges (now medallion tokens), a dead void mid-battle (combatants now share a centred band, both framed), and Dex placeholders looking like broken images (now sealed dashed slots).
35. **Habitat rooms are generated art, not CSS.** The den was a gradient while the creature was a 3D render — the mismatch was the weakest thing on screen. `npm run rooms` (scripts/generate-rooms.mjs) generates one painted 16:9 environment per type via the same Nano Banana pipeline. The prompts demand an **empty centre and floor** so the creature and decor composite on top, and low-key lighting so a glossy creature in front stays the subject.
36. **`blend` on CreatureSprite solves the dark-square problem properly.** Inside the lit room the renders' baked studio backdrop showed as a visible rectangle. Rather than attempt background removal, `blend` applies `mix-blend-mode: screen` plus a tighter mask: near-black backdrop pixels drop out against a dark scene, so the creature sits *in* the room. It stays off on the light field-guide surface, where screen would wash the art out.
37. **Minigames rebuilt to the art's standard.** Flat rectangles were the other quality gap. Bit Catch now has faceted spinning gems with motion trails, bug demons with faces, a perspective grid floor, catch particles and a combo counter; Shard Stack renders bevelled crystal layers with light/shadow facets, landing sparks, and a perfect-drop rule (dead centre keeps full width, scores a bonus); Echo Chamber uses glowing orbs with expanding ripples and a real musical scale (C5–C6).
38. **Sound is synthesized, not sampled.** `lib/audio/sfx.ts` builds every cue with the Web Audio API — no asset files, nothing to license, nothing to preload. The context is created lazily on first gesture (autoplay policy), the mute state persists in localStorage, and the mix sits low so stingers never bury narration on a recording. Caveat: this was written without being able to hear it, so levels may want tuning.
39. **Locked things are sealed slots, never silhouettes.** Greyed-out sprites turned detailed props into blobs. Locked decor and undiscovered Dex stages both render as a dashed slot with a `?`, which reads as "not yet" rather than "broken image".
40. **Skill domains teaser, deliberately scoped.** A locked strip of *skill categories* would have undersold the product: the custom-skill input already means any skill works today. Instead the strip frames the **type system** expanding (Body, Tongue, Ledger, Kitchen, Wild "soon"), which is the honest roadmap per SPEC §5 — three types now, schema supports more.
41. **Zombie dev servers on Windows.** `pkill -f next` does not reliably kill Next on Windows; a stale `npm start` kept port 3000 while a new dev server silently moved to 3002. Combined with `rm -rf .next`, that old process served HTML referencing deleted chunks, producing a convincing "Application error: client-side exception" that looked like a code bug on the habitat page. Nothing was wrong with the app. Kill by port (`Get-NetTCPConnection -LocalPort 3000 | Stop-Process`) and check the port in the server's own log before trusting a failure.
42. **The tour is a highlight reel, not a playthrough.** Retuned from 126s to **~70s full / ~50s quick** while *adding* a feature it used to skip. Beats were cut across the board (question 3.2s→1.7s, feedback hold 1.3s→0.75s, intro 3.6s→2.0s, habitat 22s→13.5s); the evolution reveal is the one beat that kept its length, because it's the money shot.
43. **The tour won't wait on Claude.** A live quiz round-trip is 5–7s of dead air per battle — most of a reel's budget. In autopilot the client timeout drops to 1.2s (and 2.2s for creature forging), so it falls through to the local bank/procedural generator almost instantly. The request still fires, so a fast response is used. Real play keeps the generous timeouts.
44. **The custom-skill forge is now *in* the tour.** It was the headline feature and the reel skipped it. The tour now types "Kubernetes" character by character, forges a creature (Kuberbyte → Kubertrix → Kubernexus), then explicitly takes the Logic starter for the rest of the run — honest, and it keeps the generated art on screen for the evolution.
45. **Stale-closure trap in timed effects.** `createCustom()` read `customSkill` from state, but the tour's `setTimeout` chain captured the mount-time closure where it was `""`, so the forge silently no-opped. Fixed by passing the skill explicitly (`createCustom("Kubernetes")`). Any function a timed effect calls should take its inputs as arguments rather than closing over state.
46. **Measuring the tour needs the recorder armed first.** Browser-tool round-trips here are ~10s, so installing a poller *after* navigating to `/?auto=…` misses the opening beats and makes the tour look broken. Load the plain page, install the recorder, then start the tour with a client-side click so it survives.
47. **Shared save store.** `useSave()` originally gave each component its own state copy; two components on one page could clobber each other's writes (found live: the demo panel reverting habitat mood). Replaced with a module-level store via `useSyncExternalStore` — one in-memory save, every subscriber re-renders on any change, single localStorage writer.
